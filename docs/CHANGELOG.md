# Changelog

## [Unreleased]

- Account page: writers now find **Post New Story** and **My stories** under their account, so starting a story no longer means knowing where the admin is. Editors and Administrators also see **Awaiting approval**. Readers see none of these. The links sit in a row of quiet outlined pills under a small **Quick links** heading. The admin header gains a **My account** link beside **View site**, so a writer can always get back to the public side.

- Pasting from Google Docs and Word: italic, bold, underline, strikethrough, superscript and subscript now arrive as real formatting instead of being lost. In the Visual editor the marks are kept as the text is pasted, and in the Markdown editor a paste that carries formatting is inserted as Markdown (`*italic*`, `**bold**`, links, headings and lists), while a plain paste behaves as before. Text typed in HTML mode gets the same treatment when it is saved, so chapters saved earlier also lose their empty `<span>` tags, hollow `<b></b>` leftovers and empty paragraphs when they are shown. Word's list paragraphs become real lists, a pasted table becomes one paragraph per cell, and Word's stray marker text no longer prints on the page. Formatting that an earlier paste already dropped cannot be recovered and has to be pasted again.

- Story covers: the story form has a **Cover** section where a writer can add a JPEG, PNG or WebP picture of up to 2 MB, with a short description for readers who cannot see it. After a picture is chosen, an optional crop frame appears over it that can be dragged or moved with sliders (the original is not kept, so the crop is made when the picture is chosen). The site checks that the file really is a picture, resizes it to a small size for lists and a larger one for the story page, and saves it again under a random name, so anything hidden in the file and details such as where a photo was taken are not kept. Covers appear on the story page and in every list of stories in Storybook (a quiet placeholder stands in for a story without one), and on the story page of the built-in theme. Replacing or removing a cover, or deleting the story, removes the old picture files. Feeds will carry covers when they are built.

- Security settings: **Settings > Security** sets how many wrong passwords start a sign-in lockout (still 5) and how long it lasts (still 15 minutes), and an address that keeps failing is now locked out for longer each time. The owner of an account that a lockout names gets an email, at most once an hour, which can be switched off; the sign-in page still answers the same whether or not the account exists. Sites behind a reverse proxy or CDN can list their proxies, and the site then reads the visitor's address and HTTPS from the headers a listed proxy adds, so the sign-in lockout, the registration limits and the Security events list see the real visitor. Forwarding headers from anyone else are ignored, and ranges that are far too wide are refused.

- Registration protection: **Settings > Spam protection** guards registration and the password-reset and confirmation-email forms. Forms carry hidden fields that only a program fills in, and a signed note of when they were shown. Registration has a shortest wait between submissions and an hourly cap per address, both counting every submission, and an automatic pause for the whole site when a flood arrives, which the dashboard reports and an administrator can end. Throw-away email services are refused by default, administrators can add their own blocked domains and a question to answer, and new sign-ups can optionally be checked with Akismet (off unless a key is entered). **Maintenance > Security events** lists what was blocked, with a retention period. A caught bot is answered like anyone else and creates nothing. Themes fire one `lf_form_fields` action inside each account form; plugins can refuse a sign-up with the `lf_registration_spam_reasons` filter. Both bundled themes are updated.

- Plugins: sites can now load plugins from `content/plugins/`. Administrators get **Maintenance > Plugins**, which lists every installed plugin with its version, author and description, checks the PHP and Lumora Fiction versions it needs, and turns it on or off. A plugin is run once as it is turned on, so one that cannot start is refused with the reason. A plugin that breaks later is skipped without taking the site down, the reason is written to the error log and the audit log once, and the dashboard flags it until it is fixed or turned off. Plugin files cannot be requested directly from the web. New hooks: `plugins_loaded`, `plugin_activated` and `plugin_deactivated`.

- Users screen: Administrators get **Users** in the admin menu, with a list of every account (newest first) that can be searched by display name or email address and filtered by role and status, and shows when each person joined. A person's page shows their role, status, email confirmation, story counts by state, and a link to their author page once something is public. Administrators can change a role, choose how an Author's stories are published (follow the site setting, publish without review, or review every story), suspend an account, and reinstate it. Suspending asks on a page of its own, signs the person out at once, stops them signing in or writing, and can also take all their published or waiting stories out of view, saying how many it took down; reinstating returns a person who never confirmed their email address to waiting for that when the site requires it. Nobody can change their own role or suspend themselves, and the site always keeps at least one active administrator, even when two administrators act at the same moment. Every change can carry a reason and is recorded in the audit log, and three new hooks (`user_role_changed`, `user_status_changed`, `user_publishing_override_changed`) let a feature react. No screen shows or searches a login name, and every change needs a security token.

- Reader features: signed-in members can bookmark a whole story or a single chapter with a button on the story and chapter pages, and keep their list on **Account > My bookmarks**, where each bookmark can be removed. A story or chapter that is later unpublished simply drops out of the list without saying why, and comes back if it is published again. The site remembers the chapter a signed-in reader opened last in each story (never for guests), shows **Continue reading** on the story page and on the home page, and the account page now has **Reading** preferences for colours, text size and reading width that follow the reader to other devices; the Storybook theme applies them, and saves a change made with its controls to the account too. Bookmarks, progress and preferences belong to one account and cannot be read or changed by another; every action is a form with a security token that works without scripts; pages built for a signed-in reader are marked private so a shared cache never keeps them. Deleting a story or chapter removes the bookmarks and places that point at it. The Storybook theme and the built-in theme draw all of it, and a theme needs a `bookmarks.php` to offer removal on the list.

- Story and author addresses now start with a number, such as `/story/42-lost` and `/author/7-ann-author`, so two stories with the same title, or two authors with the same display name, each get their own clean address instead of a numbered copy like `lost-2`. An address never changes, even when the title or name is edited. Accounts created before this keep the plain address they had.

- Search: a **Search** page in the main menu finds stories by words from the title, summary, author name or tags (every word must match), and narrows them by rating, archive warning, genre, category, fandom, tag, status, language and a range of word counts, all combinable and all switched off or on with the archive mode. Results sort by recent update, publication date, title or length. The filters in use are listed above the results, each a link that removes it. Searching works without scripts, only public stories are ever searched or counted, search text is limited in length and number of words (a search over the limit is refused with an explanation instead of run), at most a thousand matches are counted or paged through, and search pages carry a noindex header. The Storybook theme and the built-in theme draw the page.

- Account pages: visitors can register, sign in and sign out on the site itself, and the main menu offers **Sign in** and **Register** to guests and **Account** to members. The sign-in page shows the lockout wait time and offers a new confirmation email to a person who has not confirmed their address. Registering, asking for a new confirmation email and asking for a password reset all give the same answer whether or not the address has an account. A password reset link can be opened without using it up. The account page changes the display name, the email address (the old address is told) and the password (other sessions end), and lets Authors pick how the chapter editor opens unless the administrator has locked it. Pages reached through an emailed link are not cached and do not pass the link on in a Referer header. The Storybook theme and the built-in theme draw all of it, and a theme needs only an `account.php` and an `account-form` part. Visitors who must sign in to read are now sent to this sign-in page instead of the admin one, which refused accounts without admin access.

- Public archive: the site now shows its stories. The home page lists the most recently published and most recently updated stories. Every story has a page with its summary, notes, details, linked tags and chapter list, and each chapter has a page of its own with the author's notes, previous and next links and its place in the story; a finished one-chapter story opens straight to its text. Authors have pages listing their published stories, and every fandom, character, relationship, genre, tag, category, rating, warning and relationship category has a listing, all sortable by recent update, publication date, title or length and split into pages of twenty. Tags and fandoms on a story are now links. Only published stories and chapters ever appear; a draft, a story waiting for approval, an unpublished story, a deleted one, a tag that only hidden stories use, and an account that has published nothing all give the ordinary "page not found", while an author or editor who opens an unfinished story's address is taken to its private preview. A new **Visitors must sign in to read** setting under Settings > Archive sends anyone who is not signed in to the sign-in page. The built-in theme also lists stories now.

- Links between the site and the admin: signed-in Authors, Editors and Administrators now see an **Admin** link in the public main menu, in every theme, and the admin header has a **View site** link back to the home page. Guests and Readers see no trace of the admin link in the page.

- Storybook theme: the default theme, built for reading. Stories are set in a readable serif with generous spacing, and the rest of the site in the visitor's own system typeface, so nothing is loaded from an outside service. Light and dark colours follow the visitor's device and can be switched from the header, and both meet the WCAG AA contrast ratios. On a chapter, readers can choose text size and reading width, and the choices are remembered in their browser; without scripts the page simply keeps its defaults. Chapters have previous and next links at the top and bottom, and the story page shows rating, warnings, status, length, dates and tags in a layout that reads well on a phone. It has skip links, landmarks, visible focus, and a print layout that keeps the chapter text and drops the navigation. **Appearance > Theme options** offers the story typeface and whether the footer credit is shown. Story previews now also show when a story was published and last updated.

- Themes: the public side of the site is now drawn by a theme, a folder of ordinary templates in `content/themes/`. The home page and the "page not found" page come from the chosen theme, and previews of draft stories and chapters use the theme's story and chapter pages, so a preview is exactly what readers will see. A theme that is missing, unreadable, or fails while drawing a page never takes the site down: the problem is logged and a plain built-in theme draws the page instead. **Appearance > Themes** lists the installed themes and chooses the active one, and **Appearance > Theme options** holds the settings a theme offers, such as colours and reading width; an option left on "use the theme's own" never overrides the theme's design. Features add their own stylesheets, scripts and menu items in one place and every theme gets them, and only files from the site itself are accepted, so the Content-Security-Policy stays strict. Theme authors can read `docs/THEME-DEVELOPMENT.md`.

- Approval queue: Editors and Administrators get **Stories > Awaiting approval**, a list of stories waiting for review, longest waiting first, with a link to preview each one, an **Approve** button, and **Send back**, which asks for a reason. A story that is sent back becomes a draft again and its author sees the reason on the story form and a "Not approved" mark in their list until they send it again. The dashboard shows how many stories are waiting. When Settings > Archive holds a new Author's first story for approval, later stories publish directly once one of theirs has been published; an administrator can also let an Author publish without review or require review of every story they send. Every step is recorded in the audit log with who did it, and the reason when there is one. Unpublishing keeps the story, its chapters and its classification and removes it from every public list at once. Stories that were withdrawn by their author go back to being drafts; staff can take every published or waiting story of one writer out of view in a single step.

- Writing screens: Authors get a Stories menu with **My stories**, **Add a story** and, for Editors and Administrators, **All stories**. The lists search titles, filter by status, and apply publish, unpublish or delete to several stories at once, skipping any that are not yours or that still lack required classification. The story form holds the title, summary, notes, disclaimer, language, where the story stands, and every kind of classification the archive setting allows, with a mark on those that are needed before publishing. Each story has a chapter list with Move up and Move down buttons that work from the keyboard, and the chapter form has the editor, optional author's notes, a live word count, and separate Save draft and Publish buttons. Draft stories and chapters can be previewed, by their owner and by staff only. A form warns before you leave it with unsaved changes, and if your session ends while you are writing, you get your text back instead of a sign-in page, so you can sign in again and carry on without losing it. Deleting a story or chapter asks on a page of its own. The dashboard shows an Author's drafts and published stories.
- Classification: stories can carry fandoms, characters, relationships, genres, tags, original-fiction categories, ratings, archive warnings, and relationship categories. Ratings and warnings are separate, and neither is worked out from the other. Writers can propose new fandoms, characters, relationships, and tags while writing; they are usable at once and marked not yet reviewed. A new Classification screen lets administrators rename terms, add aliases, merge duplicates (every story moves to the term kept), approve proposals, delete unused terms, and choose which lists a story must have before it is submitted. Characters and relationships can belong to a fandom, so the same name in two fandoms stays two terms. The archive setting hides the lists that do not apply without deleting anything. Each term keeps a count of its public stories, and deleting a story removes its links.
- Chapter editor: write in a visual editor with a formatting toolbar, in Markdown, in HTML, or in plain text, and switch between them without losing formatting. The editors run from files stored on your site and make no requests to other sites. Text from every mode goes through the same safety filter before it is shown, so a script pasted into a chapter, or a link that runs code, never reaches a reader. The editor shows a live word count, warns before you leave with unsaved changes, can preview the chapter as readers will see it, and has separate Save draft and Publish buttons. Settings > Editor sets the editor writers start with and can lock everyone to it.
- Stories and chapters: the archive can now hold stories made of numbered chapters (a one-shot is a story with one chapter). Each story has its own address, a work status (ongoing, completed, on hiatus, or abandoned if the administrator allows it) and a separate publication state. Authors change only their own work; editors and administrators can change any. A story is shown to visitors only when it is published and has at least one published chapter, so drafts are never reachable. Word counts ignore formatting, and every change to a story is recorded in the audit log.
- Admin area: sign-in and sign-out, a dashboard that flags things needing attention, Settings > Archive (what the site publishes, who may register, what waits for approval), and Maintenance > System Information with a downloadable snapshot that leaves out passwords, the secret key, and server folders. Every settings change is recorded in an audit log. The area works in light and dark mode, with a skip link, labelled forms, and a layout for phones.
- Browser installer: checks the server, tests the database login and privileges before building anything, creates the tables with a random table prefix, sets up the first administrator, and removes itself when done. If anything goes wrong part-way it removes what it created so the form can be submitted again.
- Accounts and sign-in: each account has a private login name separate from its public display name and URL slug; roles for Administrator, Editor, Author and Reader; registration with email confirmation; sign-in that gives the same answer for an unknown account and a wrong password; a five-attempt, fifteen-minute lockout; password reset by emailed single-use link; sessions stored in the database with secure cookies; CSRF protection; standard security headers and a strict Content-Security-Policy.
- Request handling: clean URLs with a router that rejects malformed paths, a generic error page that never exposes file paths or credentials (details go to the log only), and the action and filter hooks plugins and themes build on.
- Database foundation: a configurable random table prefix, versioned database migrations that cannot run twice at once, and the initial tables for accounts, settings, sessions, and the audit log. Each account has a private login name separate from its public display name and URL slug.
- Project skeleton: front controller, directory layout, and web server rules that keep configuration, source, and storage directories from being downloaded.
