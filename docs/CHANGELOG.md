# Changelog

## [Unreleased]

- Writing screens: Authors get a Stories menu with **My stories**, **Add a story** and, for Editors and Administrators, **All stories**. The lists search titles, filter by status, and apply publish, unpublish or delete to several stories at once, skipping any that are not yours or that still lack required classification. The story form holds the title, summary, notes, disclaimer, language, where the story stands, and every kind of classification the archive setting allows, with a mark on those that are needed before publishing. Each story has a chapter list with Move up and Move down buttons that work from the keyboard, and the chapter form has the editor, optional author's notes, a live word count, and separate Save draft and Publish buttons. Draft stories and chapters can be previewed, by their owner and by staff only. A form warns before you leave it with unsaved changes, and if your session ends while you are writing, you get your text back instead of a sign-in page, so you can sign in again and carry on without losing it. Deleting a story or chapter asks on a page of its own. The dashboard shows an Author's drafts and published stories.
- Classification: stories can carry fandoms, characters, relationships, genres, tags, original-fiction categories, ratings, archive warnings, and relationship categories. Ratings and warnings are separate, and neither is worked out from the other. Writers can propose new fandoms, characters, relationships, and tags while writing; they are usable at once and marked not yet reviewed. A new Classification screen lets administrators rename terms, add aliases, merge duplicates (every story moves to the term kept), approve proposals, delete unused terms, and choose which lists a story must have before it is submitted. Characters and relationships can belong to a fandom, so the same name in two fandoms stays two terms. The archive setting hides the lists that do not apply without deleting anything. Each term keeps a count of its public stories, and deleting a story removes its links.
- Chapter editor: write in a visual editor with a formatting toolbar, in Markdown, in HTML, or in plain text, and switch between them without losing formatting. The editors run from files stored on your site and make no requests to other sites. Text from every mode goes through the same safety filter before it is shown, so a script pasted into a chapter, or a link that runs code, never reaches a reader. The editor shows a live word count, warns before you leave with unsaved changes, can preview the chapter as readers will see it, and has separate Save draft and Publish buttons. Settings > Editor sets the editor writers start with and can lock everyone to it.
- Stories and chapters: the archive can now hold stories made of numbered chapters (a one-shot is a story with one chapter). Each story has its own address, a work status (ongoing, completed, on hiatus, or abandoned if the administrator allows it) and a separate publication state. Authors change only their own work; editors and administrators can change any. A story is shown to visitors only when it is published and has at least one published chapter, so drafts are never reachable. Word counts ignore formatting, and every change to a story is recorded in the audit log.
- Admin area: sign-in and sign-out, a dashboard that flags things needing attention, Settings > Archive (what the site publishes, who may register, what waits for approval), and Maintenance > System Information with a downloadable snapshot that leaves out passwords, the secret key, and server folders. Every settings change is recorded in an audit log. The area works in light and dark mode, with a skip link, labelled forms, and a layout for phones.
- Browser installer: checks the server, tests the database login and privileges before building anything, creates the tables with a random table prefix, sets up the first administrator, and removes itself when done. If anything goes wrong part-way it removes what it created so the form can be submitted again.
- Accounts and sign-in: each account has a private login name separate from its public display name and URL slug; roles for Administrator, Editor, Author and Reader; registration with email confirmation; sign-in that gives the same answer for an unknown account and a wrong password; a five-attempt, fifteen-minute lockout; password reset by emailed single-use link; sessions stored in the database with secure cookies; CSRF protection; standard security headers and a strict Content-Security-Policy.
- Request handling: clean URLs with a router that rejects malformed paths, a generic error page that never exposes file paths or credentials (details go to the log only), and the action and filter hooks plugins and themes build on.
- Database foundation: a configurable random table prefix, versioned database migrations that cannot run twice at once, and the initial tables for accounts, settings, sessions, and the audit log. Each account has a private login name separate from its public display name and URL slug.
- Project skeleton: front controller, directory layout, and web server rules that keep configuration, source, and storage directories from being downloaded.
